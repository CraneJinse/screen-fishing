# 摸鱼搭子角色库与角色设计Skill V1

版本：游戏1.11.0；角色协议1；skill初版0.1。目标是让用户从偏好或参考图出发，做出可实际替换的完整钓鱼角色，并在信息面板管理。

## 产品设计

人物、船、鱼竿是咨询与设计的三个阶段，运行时则为一套合成动画。现有动画将船、人、钓组整体绘制，强拆实时换装容易造成握竿、鱼线、船沿和飞鱼锚点错位。V1按完整套装切换，不承诺任意人物×船×竿自由混搭；以后可在重新设计骨骼/遮罩契约后扩展。

首页新增“角色库”，位于成就之后。角色页一行一套：左侧112×122 DIP预览，中间名称、说明和人物/船/鱼竿摘要，右侧“使用角色”；当前角色描边并标注“正在使用”。480宽以下的窄布局将使用按钮放到第二行，不整体缩放字号。

顶部操作：导入角色文件夹、刷新、打开角色目录。底部说明如何调用角色设计skill。新档和旧档均自动拥有“经典搭子”；没有自定义角色时仍有可用默认项。无预览草稿有占位图；文件损坏、读取失败、导入取消、重复ID或并行导入分别提供反馈。

## 状态与存储

| 状态 | 展示与操作 |
|---|---|
| 默认角色 | 内置原版美术，始终可切换，不复制到用户目录 |
| draft | 已确认的三部分设计资料，可附预览；标为制作中，禁止切换 |
| ready | 全部动作结构通过后可选择；切换前再次完整解码验证 |
| invalid | 损坏、缺文件或不兼容；显示原因，禁止切换 |

便携版为EXE旁的user-data/characters，源码版为.screen-fishing-dev/characters。每套使用独立ASCII ID目录，character.json记设计说明，action-manifest.json和actions存动画，preview.png供选择页使用。selection.json独立保存外观选择；用户升级游戏时备份整个user-data即可保留角色。

主游戏存档、schema13、鱼类/事件收藏、金币、概率、成就、钓鱼计时均不改变。切换允许发生在等待、安静待收杆、抛竿和收杆阶段，因为V1严格固定帧时长、事件和锚点；渲染器先解码新图片，完成前保留旧图，按当前阶段的原时间点继续播放。换套装时释放旧动作缓存引用。

默认不自动切换刚导入的角色。选中角色缺失/损坏时回退经典搭子并提示，原选择文件保留。目录只在启动、刷新和导入后读取，不使用持续全盘扫描或文件监控；列表先读结构与尺寸，仅激活角色完整解码，避免全部角色图片常驻内存。

## 角色包契约

沿用逻辑192×208、2倍物理像素，每帧384×416。必须22组152帧，PNG横条；ready必须有128–1024像素透明预览。动画清单从当前游戏复制，除了file路径和顶层美术版本说明，不更改时序、帧事件、鱼获锚点、hitRect、loop或眨眼参数。

入库验证完整PNG签名、CRC、解码长度、RGBA/透明背景、每帧非空、精确尺寸与动作清单。32KB角色信息、每图12MB、整包64MB限制；禁止相对路径逃逸、软链接/junction、URL和插件脚本。只复制JSON和清单引用的PNG；其他文件忽略。技术验证不替代视觉质量审查。

导入采用角色库内临时目录→二次验证→原子改名；互斥锁防止同库同时导入。ready ID不覆盖；相同ID仅允许draft升级ready，旧草稿移到.archive。失败时不留下已注册的半包，原角色和选择继续可用。

## 进程接口

没有新增HTTP服务。preload只暴露固定IPC方法，主进程限制角色操作只能来自信息面板。

| 调用 | 参数 | 返回 |
|---|---|---|
| desktopPond.characterAction | refresh | ok与snapshot；重读目录并验证当前选择 |
| 同上 | select, id | 成功后snapshot.characters.selectedId改变；state不变 |
| 同上 | import | 打开系统文件夹选择器；取消返回canceled:true；成功回读列表 |
| 同上 | folder | 打开本游戏角色目录，失败返回error |
| game:get / game:update | 原有接口 | 增加characters:{version,selectedId,notice,entries}；assets.pet替换为当前角色 |

失败统一{ok:false,error}，成功{ok:true,snapshot}。面板按钮忙时禁用，失败toast，可再次操作。角色文字经HTML转义，图像URL只由本地主进程根据通过校验的路径生成。

## Skill设计

入口名screen-fishing-character-designer，主文件保持精简；完整咨询、生产流程、角色协议和安装流程位于references，确定性下载/入库位于scripts。首轮流程：限定项目检测→无游戏时询问下载→有多个副本则选择→确认定制意愿→参考图检查或详细无图咨询→人物→船→鱼竿→整体组合→22动作→技术与视觉验收→自动入库→回读。

普通skill安装没有自动执行钩子，检测从首次调用开始，不增加自启动任务。当前会话已有下载/定制授权和答案则复用。下载只使用CraneJinse/screen-fishing公开Releases，包括测试版；最低角色库版本1.11.0，校验SHA-256后安全解压到项目games内新目录。没有兼容版本则明确阻塞，不把旧版称为可用角色库。

完整问卷见skills/screen-fishing-character-designer/references/questionnaire.md，按2–4题一轮渐进咨询。人物分人类、小动物、幻想/机械三类；有图时区分身份/风格/构图参考，无图时必须确认类别、外形、比例、气质、配色和禁用元素。三部分逐项出图确认后再生成整套动画。

参考Codex hatch-pet的身份锁定、逐动作生成、透明处理、接触表和运行预览，不搬用其8×11或16方向协议。图像工具缺失时只交付设计，不假装生成。草稿可入库但不能冒充完成的新角色；本轮不生成个人定制美术，也不将测试副本发布为新角色。

## 验收方案

- 单元：默认与草稿、完整导入与重启选择、草稿升级归档、重复ID、路径逃逸/junction、篡改时序、损坏PNG、并行导入、未知文件隔离、选择损坏回退。
- UI：480/640/960宽布局、默认/完整/草稿状态、取消和错误反馈、实际renderer素材路径变更、等待/抛竿/待收杆/飞鱼/落船切换后state逐字段不变。
- 主线：全项目测试、语法、96项Electron烟测、发布门、整包及4种存档场景；保留当前已有用户进度。
- Skill：frontmatter验证、空项目/多副本发现、同意闸门、语义版本挑选、官方URL、校验失败、ZIP路径逃逸/大小/重复路径/链接、实际下载与导入回读。
- 明确区分：技术结构通过、可用界面与真实新角色美术完成。本轮交付角色库和初版skill，不承诺已经生成某个新形象。
